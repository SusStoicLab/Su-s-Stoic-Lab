# 表达框架

帮你在开口或动笔之前，把"想说什么"理清楚、理有力。

核心理念：**向内挖掘**。不是教你套路，是帮你找到自己真正想说的东西。

## 工作流程

按以下步骤引导用户完成表达内容的提炼。每一步都先向用户提问收集信息，再基于回答推进下一步。不要一次性走完全部流程，逐步引导、逐步输出。

**重要**：先判断用户需要什么，再决定走哪一步。很多时候用户只需要快速组织一个观点，不必走完整流程。

### 第一步：动机挖掘（向内挖）

很多人在准备表达时会从"我要讲什么"开始，但更有效的方式是先问"我为什么要讲"。

依次向用户确认以下三个问题：

1. **我相信什么？** — 你在这个话题上最核心的信念或主张是什么？
2. **我在意什么？** — 这件事跟你的什么经历、情感或利益相关？
3. **我想改变什么？** — 你希望听众听完后发生什么变化（认知改变、采取行动、情感共鸣）？

然后帮用户明确表达目的，从三个方向选一个或组合：
- 我有**方法**要教你
- 我有**主张**要告诉你
- 我有**观点**和你不一样

这一步的输出：一句话概括表达动机和目的。

**关键提醒**：动机 > 知识 > 技巧。永远通过情绪去带动人��而不是堆砌信息。如果用户说不清楚动机，继续追问，不要急着跳到下一步。

### 第二步：听众分析

了解听众才能选择正确的表达方式。向用户确认：

1. **听众是谁？** — 具体到某个画像，而不是"大家"。对话感来自对某个人说话，不是对抽象群体。
2. **听众的主要动机是什么？** — 按强度排序：
   - 得到乐趣
   - 遇到同好（背景/态度相似）
   - 获得启发（强调可迁移、可复制）
   - 见你（名人效应）
   - 看新鲜事（稀少/高价/受限）
   - 想学习（强调重要性）
   - 想早点离开（最弱，说明没吸引力）
3. **你和听众的差异有多大？** — 如果差异大，选择顺应策略：
   - **权力顺应**：听众有权力时，找到方式迎合（拐弯夸人）
   - **多数顺应**：找到多数人的共性引发共鸣，差异一旦拉高就被化解
   - **底层顺应**：让最笨的人能听懂（知识的诅咒），让最有敌意的人不误解

### 第三步：选择框架

根据表达场景，从以下框架中选择最合适的一个。

**意图路由表（按用户意图读对应 reference）**：

| 用户在做什么 | 读哪个 reference | 核心框架 |
|---|---|---|
| 日常汇报��任务简报、产品介绍、提案 | `references/frame-kongyu-san.md` | 空雨伞框架 |
| 说服决策、项目提案、竞争分析 | `references/frame-3c.md` | 3C说服框架 |
| 面试答辩、快速说服、需要抓注意力 | `references/frame-pyramid.md` | 金字塔框架 |
| 获奖感言、个人故事、团队回顾 | `references/frame-timeline.md` | 时间线框架 |

如果用户不确定用哪个，默认推荐**空雨伞框架**——它几乎适用于所有需要说服或说明的场景。

### 第四步：组织内容骨架

根据选定的框架，帮用户填充内容：

1. 把第一步的动机和目的放入框架的核心位置
2. 根据听众分析调整内容的深浅和切入角度
3. 列出每个段落/章节要传递的核心信息（不超过3个要点）
4. 检查是否有逻辑断层或信息跳跃

输出格式：
```
【表达目的】一句话
【听众画像】+ 顺应策略
【选用框架】框架名称
【内容骨架】
- 第一部分：核心信息 + 支撑材料
- 第二部分：核心信息 + 支撑材料  
- 第三部分：核心信息 + 支撑材料
【关键提醒】情绪驱动点、避免的坑、收束方式
```

## 常见错误（反模式）

| 错误 | 表现 | 怎么避免 |
|------|------|----------|
| **堆砌信息** | 讲了很多，但听众不知道重点 | 每个部分只传递1个核心信息，不超过3个要点 |
| **没有动机** | 为了讲而讲，听众感受不到你的在乎 | 先挖清楚"我为什么要讲"，说不清楚就继续挖 |
| **不了解听众** | 对着"大家"说话，没有对话感 | 具体到某个画像，想象你在跟一个人聊天 |
| **框架不对** | 用时间线讲提案，用金字塔讲故事 | 按场景选框架，不确定就用空雨伞 |
| **诚实不足** | 说的不是自己真正相信的 | 记住：诚实胜于舒适，说自己真正相信的话 |

## 自检清单

输出内容前，用以下问题检查：

- [ ] 动机清楚吗？听众能感受到你为什么在乎这个话题吗？
- [ ] 听众画像具体吗？是在跟"一个人"说话还是跟"大家"说话？
- [ ] 框架选对了吗？这个场景用这个框架合适吗？
- [ ] 每个部分的核心信息不超过3个要点吗？
- [ ] 逻辑连贯吗？有没有跳跃或断层？
- [ ] 说的是自己真正相信的话吗？

## 注意事项

- 用户的表达风格应保持自己的特色，框架是骨架不是模板，不要千篇一律
- 如果用户只需要快速组织一个观点，不必走完整流程，直接从第三步开始
- "向内挖掘"是核心理念——帮用户找到真正想说的东西，而不是帮他编造内容
- 好的表达是"诚实胜于舒适"，鼓励用户说自己真正相信的话
