# 空雨伞框架

最万能的框架——几乎适用于所有需要说服或说明的场景。

## 结构

```
空（背景/现状）→ 雨（问题/挑战）→ 伞（方案/行动）
```

## 为什么好用

- 符合人的认知习惯：先知道"现在啥情况"，再知道"有啥问题"，最后知道"咋办"
- 听众不会迷路：每一步都在推进，不会突然跳到结论
- 适用范围广：工作汇报、产品介绍、提案、日常说服，都能用

## 各部分要点

### 空（背景/现状）
- **做什么**：描述当前的情况、背景、前提
- **关键点**：客观、简洁、让听众建立共同的认知基础
- **常见错误**：
  - 背景太长，听众已经不耐烦了还没进入正题
  - 背景太主观，夹带了自己的判断而不是事实
  - 假设听众已经知道，跳过背景直接讲问题，结果听众没跟上

### 雨（问题/挑战）
- **做什么**：点出当前的困难、矛盾、痛点
- **关键点**：让听众感受到"确实是个问题"，产生解决的动机
- **常见错误**：
  - 问题描述太抽象，听众感受不到紧迫性
  - 把问题和方案混在一起，还没讲清楚问题就急着给方案
  - 问题太多太杂，听众抓不住重点

### 伞（方案/行动）
- **做什么**：给出具体的解决方案、行动计划
- **关键点**：方案要针对"雨"里提出的问题，逻辑上能对应
- **常见错误**：
  - 方案和前面的问题对不上，听众会觉得"你说了半天问题，然后呢？"
  - 方案太笼统，没有可执行性
  - 方案太多，听众记不住

## 示例

### 工作汇报
**空**：这个季度我们完成了3个项目，客户满意度85%，比上季度提升5个百分点。

**雨**：但新客户的获取成本增加了20%，主要是因为竞品开始打价格战，我们的获客效率在下降。

**伞**：建议下季度调整策略，把30%的获客预算转到老客户推荐计划，预计能把获客成本降低15%。

### 产品提案
**空**：目前我们的App日活用户10万，平均使用时长25分钟。

**雨**：但用户留存率在第二周下降了40%，主要是因为新用户上手困难，核心功能学习成本高。

**伞**：建议开发一个7天新手引导计划，分阶段解锁核心功能，配合每日任务激励，预计能把第二周留存率提升到70%。

## 自检清单

- [ ] 背景是否简洁客观，没有夹带判断？
- [ ] 问题是否具体，听众能感受到紧迫性？
- [ ] 方案是否针对问题，逻辑上能对应？
- [ ] 整个表达是否在3-5分钟内能讲完？
