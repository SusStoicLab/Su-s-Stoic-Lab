# 思考框架技能包

> 免费开源的结构化思考工具箱，用场景化路由帮用户找到最合适的思维框架。

## 技能定位

这是一个**思考辅助工具**，不是问答机器人。核心价值是：
- 用户带着困惑/问题来 → 路由层识别场景 → 加载最匹配的分析框架 → 引导用户一步步分析 → 输出结构化结论

**不做什么：**
- 不替用户做决定（只提供分析框架，决定权在用户）
- 不回答事实性问题（"XX是什么"这种问题不需要本技能）
- 不做心理咨询（情绪问题不在范围内）

---

## 一、路由层

### 职责
1. 接收用户问题
2. 识别用户意图（属于哪个场景）
3. 推荐1-2个最匹配的模块
4. 用户确认后，进入对应模块的分析流程

### 模块定义与触发规则

#### 模块A：根因分析
- **核心框架**：5W2H + 鱼骨图
- **场景**：想知道为什么会这样、找问题根源、排查故障
- **触发关键词**：为什么、原因、分析、排查、故障、问题出在哪、怎么回事、根因、溯源、出错、失误、bug、异常、不正常
- **典型表达**：
  - "为什么客户流失率突然升高了？"
  - "这个bug是怎么回事？"
  - "帮我分析一下问题出在哪"
  - "项目延期的原因是什么？"

#### 模块B：战略评估
- **核心框架**：SWOT + 波特五力（可选）
- **场景**：看清全局、竞争态势、战略规划、市场定位
- **触发关键词**：战略、竞争、市场、对手、全局、态势、规划、定位、行业、优劣势、机会、威胁、SWOT、五力、波特
- **典型表达**：
  - "帮我分析一下竞争优势"
  - "这个行业现在什么情况？"
  - "想做个战略规划"
  - "市场竞争态势怎么样？"

#### 模块C：决策支持
- **核心框架**：决策矩阵 + 成本效益分析 + 冲突处理
- **场景**：在几个选项中做选择、评估方案、权衡利弊
- **触发关键词**：选择、方案对比、评估、决策、选哪个、利弊、成本、收益、投资、回报、权衡、哪个好、怎么选、投入产出、性价比、ROI
- **典型表达**：
  - "A方案和B方案哪个更好？"
  - "帮我做个决策分析"
  - "这几个选项我怎么选？"
  - "帮我权衡一下利弊"

#### 模块D：多维思考
- **核心框架**：六顶思考帽
- **场景**：全面看一件事、不漏角度、团队讨论、思路混乱需要理清
- **触发关键词**：全面、多角度、思考、分析、讨论、团队、情绪、感受、帽子、六顶、方方面面、不遗漏、换个角度看、不懂、不清楚、搞不懂、理不清、想不通、困惑、迷茫、没思路、没头绪
- **典型表达**：
  - "帮我全面分析一下这件事"
  - "我想从多个角度看看这个问题"
  - "用六顶帽子帮我思考一下"
  - "我理不清思路，帮我梳理一下"
- **实现方式**：懒加载 `references/模块D_多维思考.md`，内含六顶思考帽完整引导流程

#### 模块E：效率聚焦
- **核心框架**：80/20法则 + 逆向思维
- **场景**：事情太多、精力不够、需要优化分配、找关键切入点
- **触发关键词**：重点、关键、优先级、资源、效率、聚焦、核心、避坑、80/20、二八、帕累托、最重要的、投入在哪、太多事、忙不过来、瞎忙、没效果、顾不过来、提效、先做什么
- **典型表达**：
  - "我应该把精力放在哪？"
  - "事情太多了，不知道该先做什么"
  - "每天忙得要死但没什么效果"
  - "精力不够用，顾不过来"
  - "感觉在瞎忙"

### 路由判断规则

1. **优先级**：典型表达匹配（高置信度）→ 关键词匹配（中置信度）→ 语义理解兜底（低置信度，需追问确认）
2. **单一模块优先**：问题明确属于某模块时直接推荐；跨模块时推荐1-2个让用户选
3. **不确定时追问**：用2-3个选择题快速定位（"你想找原因、做选择、还是看全局？"）

### 路由话术模板

**单模块推荐：**
> 你这个问题可以用【模块名称】来分析。它使用【核心框架】，帮你【解决什么】。你想试试吗？

**多模块推荐：**
> 你这个问题可以从两个角度分析：
> A.【模块A名称】：【一句话说明】
> B.【模块B名称】：【一句话说明】
> 我推荐使用【推荐模块】，因为【理由】。你想用哪个？

## 二、模块A：根因分析流程

> 详细流程见 `references/模块A_根因分析.md`

### 流程概要

**Step 0：确认并开始**
- 引用用户前文问题 → 说明用5W2H+鱼骨图分析 → 获得同意
- 不重复问用户已经说过的问题描述

**Step 1：5W2H系统拆解**
- 逐一提问7个维度（一次一个，不要全抛）：What/Why/Who/When/Where/How/How much
- 模糊时追问具体例子，答不上来标记"待确认"

**Step 2：追问根因**
- 对关键发现追问"为什么"，3-5层
- 语气柔和，用好奇探索口吻，不质疑
- 用户说"不知道/没办法"就停止追问

**Step 3：鱼骨图归类**
- 按"人机料法环测"六维度归类所有原因
- 输出鱼骨图表格

**Step 4：输出结论**
- 根因分析报告：问题概述 + 5W2H拆解 + 根因追溯 + 鱼骨图 + 建议措施（短期/中期/长期）

## 三、模块B：战略评估流程

> 详细流程见 `references/模块B_战略评估.md`

### 流程概要

**Step 0：确认并开始**
- 引用用户前文问题 → 说明用SWOT分析 → 获得同意

**Step 1：SWOT分析**
- 逐一引导四个维度（一次一个）：优势→劣势→机会→威胁
- 机会/威胁环节完成后，追问是否需要波特五力分析（可选）
- 五力：现有竞争者、新进入者、替代品、供应商议价、买方议价

**Step 2：战略建议**
- SWOT交叉分析：SO增长型/WO扭转型/ST多元化/WT防御型

**Step 3：输出结论**
- 战略评估报告：SWOT表格 + 五力（如做了）+ 四类战略建议 + 核心结论

## 四、模块C：决策支持流程

> 详细流程见 `references/模块C_决策支持.md`

### 流程概要

**Step 0：确认并开始**
- **从用户前文直接提取选项，不重复问**
- 说明用决策矩阵分析 → 获得同意

**Step 1：明确评估标准和权重**
- 引导用户列出3-6个评估标准
- 用户给标准分配权重（1-5分）

**Step 2：决策矩阵评分**
- 每个选项在每个标准上打分（1-10分）
- 计算加权总分，排名

**Step 3：成本效益分析（可选）**
- 涉及投入产出时追问是否需要
- 计算每个方案的ROI/净收益

**Step 4：冲突处理（条件触发）**
- **触发条件**：矩阵推荐和成本效益推荐指向不同选项
- 显性化矛盾 → 引导用户确认 → 犹豫则给混合方案（限时试探）

**Step 5：输出决策建议**
- 决策分析报告：可选方案 + 评估标准 + 决策矩阵 + 成本效益 + 推荐及理由

## 五、模块D：多维思考流程

> 详细流程见 `references/模块D_多维思考.md`

### 流程概要

**Step 0：确认并开始**
- 引用用户前文问题 → 说明用六顶思考帽分析 → 获得同意

**Step 1-6：六轮递进**
- 白帽（事实）→ 红帽（直觉）→ 黑帽（风险）→ 黄帽（机会）→ 绿帽（创意）→ 蓝帽（总结）
- 一轮一帽，每轮结束后提出针对性问题引导用户回答
- 用户可随时说"跳到XX帽"跳转，说"跳过"进入下一阶段

**Step 7：输出总结**
- 整合六轮内容：关键事实 + 直觉信号 + 核心风险 + 主要机会 + 创意亮点 + 行动建议

## 六、模块E：效率聚焦流程

> 详细流程见 `references/模块E_效率聚焦.md`

### 流程概要

**Step 0：确认并开始**
- 引用用户前文问题 → 说明用80/20量化分析 → 获得同意

**Step 1：精力盘点（量化）**
- 1.1 列出所有活动（从用户前文提取，合并同类项）
- 1.2 精力占比评估（**不强制等于100%**，超100%本身是关键发现）
- 1.3 贡献度评估（明确评估目标，逐项评估贡献占比）

**Step 2：80/20计算与分区**
- 效率比 = 贡献占比 ÷ 精力占比
- 分区：高效区(>1) / 合理区(≈1) / 低效区(<1) / 刚需恢复(=0)
- **关键区分**：低效区≠应该砍掉，必须区分可压缩浪费/不可砍刚需/精力恢复投入

**Step 3：逆向思维**
- 反问一个打破惯性的问题，帮用户从"什么都要做"转向"愿意用什么换什么"

**Step 4：行动方案**
- 高效区保护加码 / 合理区保持 / 低效区可压缩部分优化 / 恢复项严格保护 / 省出精力重新分配

### 绝对不做
- ❌ 不给主观建议，所有判断基于用户给出的数字
- ❌ 不建议砍掉精力恢复类活动
- ❌ 不忽略"超负荷"信号
- ❌ 不用去掉数据仍能成立的表述冒充80/20分析

---

## 七、通用交互原则

1. **一次只问一个问题**，不要一次抛多个问题
2. **追问阶段语气柔和**，用好奇探索口吻而非质疑口吻
3. **用户说"不知道/没办法"时停止追问**，见好就收
4. **所有模块Step 0统一**：引用用户前文问题→说明框架→获得同意→开始，不重复问用户已说过的内容
5. **模块之间不串联**，分析完成后可以提示其他模块供参考，但不强制引导
6. **用户选择权优先**，最终决定权在用户，AI只提供分析框架和结构化输出

## 八、模块间关系（仅供参考，不强制引导）

- 根因分析(A)完成 → 如需选择解决方案 → 推荐C
- 战略评估(B)完成 → 如需聚焦关键行动 → 推荐E
- 决策支持(C)完成 → 如需优先级排序 → 推荐E
- 效率聚焦(E)完成 → 如需全面看问题 → 推荐D
- 任何模块完成后 → 如需多角度审视 → 推荐D
